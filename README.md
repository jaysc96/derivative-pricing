# derivative-pricing

An option pricing library with six independently implemented methods, and a web
calculator on top of it.

The six methods are the point. A closed form, two lattices, two Monte Carlo
estimators and a PDE solver share no implementation path, so a mistake in one
has to be made identically in several others to survive. That property is what
the test suite spends its time on, and what the evidence below reports.

**European methods agree to within 0.04** across the moneyness and maturity
grid; American methods, which have no closed form to anchor to, agree to within
0.15. Finite-difference Greeks match Black-Scholes to **1.02%** at worst.

Full tables: [docs/evidence/convergence.md](docs/evidence/convergence.md),
regenerated by `scripts/generate_evidence.py` and verified byte-for-byte in CI.

## Install and test

Python 3.12 or newer.

```
git clone https://github.com/jaysc96/derivative-pricing.git
cd derivative-pricing
python -m venv .venv && source .venv/bin/activate
pip install -e ".[app,dev]"
pytest
```

About 2000 tests, roughly three minutes. No test touches the network.

The calculator is a React client (`client/`, Node 20+) against a Flask JSON
API (`api/`) — build the client once, then run the same Flask app that serves
both:

```
cd client && npm install && npm run build && cd ..
flask --app app run
```

`npm test` inside `client/` runs its own suite (Vitest) separately from
`pytest`. Or run the evidence and benchmark generators directly:

```
python scripts/generate_evidence.py --check   # convergence artifact is current
python benchmarks/bench_pricing.py            # timings against the recorded baseline
```

## What the library does

```python
from pricing import European_Option, American_Option

opt = European_Option("call", 100.0, 100.0, 0.05, 0.20, 0.02, 1.0, "BSM")
result = opt.priceOption()
result.price, result.delta, result.vega
```

Every method returns the same `PriceResult` — a scalar price at the contract's
spot plus its Greeks — so code that prices a chain never has to know which
method produced a number.

| Method | Technique | European | American |
|---|---|---|---|
| `BSM` | Black-Scholes-Merton closed form | yes | — |
| `BT` | Cox-Ross-Rubinstein binomial tree | yes | yes |
| `TT` | Trinomial tree | yes | yes |
| `MC` | Monte Carlo, antithetic variates | yes | — |
| `LSMC` | Longstaff-Schwartz least-squares Monte Carlo | — | yes |
| `FD` | Crank-Nicolson finite differences | yes | yes |

Trees and Monte Carlo take a discretization; finite differences derive their
grid from the contract and price without configuration.

## Evidence

### The tests were shown to catch the defects, not assumed to

This codebase started with four real pricing defects. The convergence suite was
written **before** any of them were fixed, and its 152 failures were captured
and committed so the suite's diagnostic power is checkable rather than asserted:
[docs/evidence/pre-fix-failures.md](docs/evidence/pre-fix-failures.md).

The failures partitioned cleanly by cause — 80 from a Monte Carlo drift that
omitted the dividend yield, 48 from a Longstaff-Schwartz regression that went
singular on deep out-of-the-money contracts, 24 from Greek estimation. Each fix
was then verified load-bearing by reverting it alone.

That document also records a finding that went the other way. A fifth suspected
defect — the American finite-difference solver testing early exercise against
the previous time slice rather than the payoff — turned out to cost nothing:
the two rules coincide at every node, verified by running both inside the solver
over 199 time steps with zero divergence. It was fixed for robustness, and the
suite does not pretend to catch it.

### Performance

The four tree methods run **19.6x to 64.7x** faster than their original
implementations, from vectorizing the backward pass and hoisting the American
stock lattice out of the loop:
[docs/evidence/benchmarks.md](docs/evidence/benchmarks.md).

Every optimization is arithmetic-preserving, asserted as **exact equality**
against the scalar loops it replaced across 240 contracts — not agreement within
a tolerance, which for a refactor claiming to change nothing would prove nothing.

### An outside reference, with a caveat

The convergence suite is anchored to Hull's worked examples. **The parameter
sets and printed values are Hull's, but the edition and page are unverified**,
so this is not yet an independent citation. What it is: agreement with a
separate implementation that shares no code with the library, reproducing the
printed figures to their stated precision.

One trap is recorded there because it nearly landed: Hull's 4.49 for the
American put is a **five-step** tree, and the converged value is 4.2842.
Anchoring a 200-step method to the printed figure would have been wrong by 0.2
while appearing to agree with the book.

## Market data and implied volatility

A scheduled job captures live option chains for a tracked set of six liquid
names (SPY, QQQ, IWM, AAPL, MSFT, NVDA) into a point-in-time archive: every
observed quote is stored as of the moment it was observed, never overwritten,
so a chain read for a past moment reflects only what was actually knowable
then. Implied volatility is inverted from the stored quotes by the same
pricing library above — bracketed root-finding against the American tree,
since every tracked symbol is American-style — and stamped with an explicit
engine version (`pricing.ENGINE_VERSION`), so a solver change can rebuild the
derived table wholesale from the raw archive instead of silently mixing old
and new numbers.

Both layers regenerate into the repository on every capture:
[docs/evidence/coverage.md](docs/evidence/coverage.md) (accumulated history
and quote coverage by strike and expiry, available as soon as raw capture
runs) and [docs/evidence/surface.md](docs/evidence/surface.md) (the derived
implied volatility surface). Unlike the convergence tables above, both read a
store that changes on every capture rather than pure code, so neither is
checked byte-for-byte — each records its own generation time and the
timestamp of the snapshot it describes instead.
