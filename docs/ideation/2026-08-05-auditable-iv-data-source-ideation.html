Grounding Context

Codebase Context

A Python 3.12 option-pricing library, pricing/, with six methods split by exercise style: closed-form Black-Scholes-Merton, binomial and trinomial trees, Monte Carlo with antithetic variates, Longstaff-Schwartz least-squares Monte Carlo, and Crank-Nicolson finite differences. Every method returns one PriceResult — a scalar price at the contract's spot plus its Greeks. 1,719 tests pass in about three minutes; none touch the network.

Foundation is complete. Four pricing defects were found and fixed, and the 152 pre-fix failures were captured and committed so the suite's diagnostic power is checkable rather than asserted. Convergence evidence is generated by scripts/generate_evidence.py and verified byte-for-byte in the test suite. The four tree methods run 19.6× to 64.7× faster after vectorization, with equivalence to the scalar loops asserted as exact equality.

Two of the three strategy tracks are largely unbuilt: the archive has zero days of history, and there is no access layer at all. A Flask calculator is the only consumer today.

Provider spike, first observation

30 requests against yfinance over six candidate symbols, no failures, 3,681 contracts. 69.1% carried both a non-zero bid and a non-zero ask. Three findings shape several ideas below: ask is populated on 100% of contracts, so the quality gate is a rule about bids alone; expiry-day contracts are a distinct population at 42% two-sided against 76–83% further out; and lastTradeDate is 100% populated but times trades, not quotes, so it is a liquidity signal rather than a freshness one. The provider also returns its own impliedVolatility on 100% of contracts.

External context

Exchanges do not publish IV or Greeks at all — marketdata.app states plainly that traders see different numbers across platforms because "everyone is using different methods and assumptions." A QuantNet thread puts a magnitude on the American case: QuantLib returned 141.3 where Bloomberg showed 116.124 for the same American call, a 22% gap, with the exercise-style assumption named as the suspect. Commercial history is real money — IVolatility around $50/month, ORATS $100+/month, OptionMetrics institutional-only. EODHD offers roughly 2.5 years of contract-level history with pre-computed Greeks and IV.

Vendor disagreement, attributed

Description
Store the provider's own IV alongside every captured quote, compute your own, and publish the difference as a first-class column — then attribute the gap to its cause by re-pricing under each competing assumption in turn. A user sees not just that the numbers differ but which assumption accounts for how much of the gap.
Axis
Provenance and re-derivation
Basis
direct: the provider spike found impliedVolatility populated on 100% of 3,681 contracts, so the comparison input is already free and already being fetched. external: marketdata.app attributes cross-platform IV differences to "different methods and assumptions" but publishes no attribution; nothing found in the search does.
Rationale
This is the entire strategy demonstrated on day one, before a single day of history has accrued. Every other idea here needs an archive first; this one needs one capture. It also converts the product's core claim from an assertion a reader must accept into a number they can look at, which is exactly the gap the target problem names.
Downsides
Attribution requires re-pricing each contract several times, multiplying engine cost per capture. Naming a competitor's number as wrong invites argument you must be able to win, so the attribution has to be right. And a provider that stops publishing IV removes the input.

The verifier — reproduce any published row

Description
A single command that takes one published row, pulls the archived raw quote and the stamped engine version it names, recomputes the number, and prints match or mismatch. Ship it as a CLI first; a WebAssembly build later lets a stranger verify in a browser tab with nothing installed and no trust extended.
Axis
Provenance and re-derivation
Basis
external: reproducible builds in software supply chain, where the claim "this binary came from this source" is worthless as an assertion and load-bearing as a rerunnable check. direct: the repository already does this to itself — scripts/generate_evidence.py --check regenerates the convergence artifact and fails the test suite if it differs, so the pattern is built and proven on a smaller surface.
Rationale
The strategy says auditability is the guiding policy and accuracy is what it makes provable. Nothing converts that from positioning into product faster than a button. It also changes the sales conversation: instead of asking to be believed over ORATS, you hand over a command.
Downsides
It sets a standard you must then never break — a verifier that fails on your own historical rows is worse than never having shipped one, which forces engine-version discipline earlier than would otherwise be comfortable. The WASM build is real work and the pricing library is NumPy and SciPy, so a browser build likely means a reimplementation rather than a port.

Publish the early-exercise premium as a column

Description
For every single-stock contract, publish both the American value and what the same contract would be worth under European exercise, and expose the difference as its own column. Optionally extend to a small set of named assumption bundles — a rate-curve choice, a dividend treatment — so a user sees the sensitivity rather than one number presented as fact.
Axis
Engine reach
Basis
external: the QuantNet thread reports 141.3 against Bloomberg's 116.124 for one American call, with exercise style named as the suspect — a 22% error on a number people size positions with. direct: this library already has three American methods (binomial, trinomial, Longstaff-Schwartz) and a finite-difference solver that prices American exercise correctly, so the second number costs a re-price, not a research project.
Rationale
It converts the accuracy half of the strategy into something a user can see rather than trust, and it is the one claim here that competitors cannot cheaply match — a vendor inverting with Black-Scholes cannot publish this column without admitting to it. It is also the most direct use of the six-method engine, which is otherwise the project's largest sunk investment.
Downsides
Doubles or triples pricing cost per contract. The premium is near zero for most out-of-the-money short-dated contracts, so the column reads as noise across much of the chain and needs presenting carefully to avoid looking padded. It also invites the question of which dividend model you used, which then has to be answered properly rather than defaulted.

One symbol, exhaustively

Description
Rather than four to six symbols at four near expiries, take a single liquid underlying and capture it completely — every expiry the provider lists, every strike, several times a day — and publish an honest coverage map beside it showing what was two-sided, what was stale, and what was missing at each capture.
Axis
History acquisition
Basis
direct: STRATEGY.md already names coverage breadth as a non-goal — "three symbols someone can audit over three thousand they must take on faith." The spike measured 32 expiries available for SPY against the four sampled, so the depth exists and is not being taken. direct: the same spike found the two-sided fraction varies from 42% to 89% by expiry, which means a coverage map carries real information rather than being a formality.
Rationale
Depth is the shape of the strategy applied to the archive, and it makes everything else cheaper: one symbol fixes N, bounds the rate-limit question, and makes intraday capture affordable — which in turn makes the history genuinely differentiated, since the commercial vendors sell end-of-day. It also converts the coverage weakness into published evidence instead of an omission.
Downsides
A single-symbol dataset is much less useful to most people, and cross-sectional work becomes impossible, which closes off some derived signals entirely. If the chosen symbol turns out to be a bad representative, months of accrual are spent on the wrong name — and the whole point of accruing is that you cannot re-run it.

Reanalysis releases

Description
Treat the derived data as a rebuildable product rather than an accumulating one. When the engine improves, reprocess the whole archive and publish it as a numbered, dated release alongside the raw quotes and the previous releases, so a user can pin a version, cite it, and diff two of them. Old releases stay published rather than being replaced.
Axis
Derived signals
Basis
external: climate reanalysis — ERA5 and its predecessors — solves exactly this shape, reprocessing decades of unchanged raw observations with the current best model and shipping numbered generations, because the observations and the interpretation of them improve on different clocks. direct: the strategy already commits to version-stamping the pricer and re-derivability from the archive, so the capability is a stated requirement and this names the product built on it.
Rationale
A conventional vendor cannot retroactively improve history because they never kept the raw inputs — their archive is their output. Keeping raw quotes verbatim means every engine fix improves the entire past, which turns the four defects already fixed here from an embarrassment into a demonstration of the mechanism. This is the strategy's deepest source of compounding.
Downsides
Real operational weight: storage multiplies per release, and users pinned to different versions will report inconsistent numbers to each other. There is a subtle trap — a reanalysis must not destroy point-in-time correctness, since a backtest needs what was knowable at the time, not the best estimate computed later. That distinction has to be designed in, not retrofitted. And with no history yet, this pays nothing for months.

Engine-as-product, as a licensing hedge

Description
Package the pricer plus the verifier so a user can point it at option data they are already entitled to — their broker feed, their EODHD subscription — and get the same auditable IVs without you redistributing anything. The published dataset and the runnable engine become two routes to the same output.
Axis
Consumption
Basis
reasoned: the strategy's archive track now depends on ingesting third-party historical quotes and republishing values derived from them into a public repository. Redistribution terms on historical options data are typically restrictive, and the derived-work question is unresolved — flagged as open when the strategy was written. If that resolves badly, the entire backfill half of the archive track is blocked, and the only asset that survives is the engine. Building the engine path deliberately turns a single point of failure into two routes.
Rationale
It is insurance on the most load-bearing unresolved risk in the strategy, and it happens to serve a real audience anyway — the systematic trader who already pays for data and wants trustworthy IVs from it, rather than another subscription. It also reaches users whose compliance posture forbids third-party marks entirely, which is the "defensible number" segment named as the later expansion.
Downsides
Value is contingent on a risk that may not materialize, and building against a hypothetical is how projects acquire unused surface area. It also cuts against the data product: a user running the engine on their own feed has no reason to buy your history. And supporting arbitrary input formats is an open-ended maintenance commitment.
